# deka crawler — คำพิพากษาศาลฎีกา (deka.supremecourt.or.th)

โค้ดชุดนี้ **ยังไม่ได้รันแบบเต็ม** — ใช้ทดสอบนำร่องเท่านั้น (ดูหัวข้อ "ข้อควรรู้ก่อนรันเต็ม")

## สิ่งที่เว็บศาลเผยแพร่จริง (จากการนำร่อง 5 ต.ค. 2569)

- เว็บเป็นเพจ PHP (CodeIgniter) ธรรมดา ไม่ใช่ SPA, **ค้นหาได้โดยไม่ต้องล็อกอิน** (ปุ่มล็อกอิน/สมัครสมาชิกถูกซ่อนอยู่)
- ผลค้นหาแบ่งหน้า 20 คดี/หน้า และ **แต่ละหน้ามีข้อความครบในตัว** (ย่อสั้น + ย่อยาว + มาตรา + คู่ความ + องค์คณะ + ศาลล่าง + เลขคดีดำ) ไม่มีหน้ารายละเอียดแยก (เป็น modal ในหน้าเดียวกัน)
- **เว็บไม่ได้ให้ตัวคำพิพากษาฉบับเต็ม** — มีเฉพาะ "ย่อสั้น" และ "ย่อยาว" ที่ศาลจัดทำ (แหล่งที่มา: กองผู้ช่วยผู้พิพากษาศาลฎีกา) ย่อยาวว่าง 9 จาก 30 คดีในตัวอย่าง (ส่วนใหญ่คดีเก่า)
- ไม่มี: วันที่พิพากษา, ประเภทคดี, คำสำคัญ
- รวม **133,210 คดี** (113 กลุ่มปี: ส่วนใหญ่ พ.ศ. 2463–2569 + ระเบียนปีผิดปกติ 7 รายการ เช่น ปี 4, 254, 2015) — ตัวเลขรายปีอยู่ในหน้า `/search/year`
- ชื่อคู่ความ: บางคดีศาลปิดชื่อ (เช่น `นาย ข.`) บางคดีแสดงเต็ม — เก็บ "ตามที่ศาลเผยแพร่" ไม่แก้
- เว็บแจ้งท้ายหน้า "© ลิขสิทธิ์โดยศาลฎีกา" ไม่มีหน้าเงื่อนไขการใช้งาน, ไม่มี robots.txt, คู่มือ (`/uploads/manual.pdf`) ไม่กล่าวถึงการทำสำเนา/อัตโนมัติ

## ขั้นตอนสำหรับเจ้าของระบบ

### 1) เปิดเบราว์เซอร์ (หน้าต่างที่มองเห็นได้, โปรไฟล์แยก)

```powershell
Start-Process 'C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe' -ArgumentList '--remote-debugging-port=9333',"--user-data-dir=$env:LOCALAPPDATA\lawcraft-deka-profile",'https://deka.supremecourt.or.th'
```

- ปัจจุบันไม่ต้องล็อกอิน หากวันหนึ่งเว็บบังคับล็อกอิน ให้ **ท่านล็อกอินเองในหน้าต่างนี้** (รวม captcha/OTP) — สคริปต์ไม่รับ/เก็บรหัสผ่านใดๆ และไม่แก้ captcha
- ห้ามปิดหน้าต่างระหว่างรัน (ใช้แท็บ deka แท็บเดียว; สคริปต์จะนำทางแท็บนั้นเอง)

### 2) รันนำร่อง (ปีเดียว 1 หน้า = 20 คดี)

```powershell
cd E:\boi\app\scripts\deka
node crawl.mjs --years 2569 --max-pages 1
```

ผลลัพธ์ไปที่ `%LOCALAPPDATA%\lawcraft-deka-data\` (**นอก repo — ห้ามใช้ --out ใน repo, สคริปต์จะปฏิเสธ**): `2569.jsonl`, `checkpoint.json`, `crawl.log`

### 3) รันช่วงปี (ต่อจากเดิมได้เสมอ)

```powershell
node crawl.mjs --from 2560 --to 2569            # ใหม่ → เก่า
node crawl.mjs --years 2538,2540 --delay-min 4000 --delay-max 8000
```

| ตัวเลือก | ความหมาย |
|---|---|
| `--from/--to` หรือ `--years` | ปี พ.ศ. |
| `--out DIR` | โฟลเดอร์ผลลัพธ์ (ค่าเริ่มต้น `%LOCALAPPDATA%\lawcraft-deka-data`) |
| `--delay-min/--delay-max` | หน่วงระหว่างหน้า (ms) สุ่มในช่วงนี้ ขั้นต่ำ 3000 |
| `--max-pages N` | จำกัดจำนวนหน้าที่โหลดต่อการรัน |
| `--port` | พอร์ต CDP (ค่าเริ่มต้น 9333) |

### 4) ติดตามความคืบหน้า

```powershell
Get-Content "$env:LOCALAPPDATA\lawcraft-deka-data\crawl.log" -Wait -Tail 20
Get-Content "$env:LOCALAPPDATA\lawcraft-deka-data\checkpoint.json"
```

### 5) หยุด

- หยุดอย่างปลอดภัย: สร้างไฟล์ `%LOCALAPPDATA%\lawcraft-deka-data\STOP` (สคริปต์จบหลังหน้าปัจจุบัน) แล้วลบไฟล์นี้ก่อนรันใหม่
- หรือกด Ctrl+C (checkpoint ถูกบันทึกทุกหน้า)
- รันซ้ำคำสั่งเดิมเพื่อ **ต่อจากเดิม** (ปีที่ `done` ข้าม, ปีที่ค้างเริ่มจาก `nextPage`)

### สคริปต์หยุดเองเมื่อ

พบ HTTP 403/429, ข้อความ captcha/บล็อก, หน้าที่ได้ไม่ตรงหน้าที่ขอ (session หลุด), อ่านจำนวนหน้าไม่ได้, ไม่มี docId (โครงสร้างเว็บเปลี่ยน), หรือครบ `--max-pages` — **ห้ามลองใหม่ทันที** ให้ตรวจ `crawl.log` และรอ/ติดต่อศาล

## รูปแบบข้อมูล (1 บรรทัด JSON ต่อคดี)

`docId` (คีย์จริงของศาล), `titleRaw`, `docType`, `caseNo` (อาจเป็นช่วง เช่น `9996 - 9997`), `year`, `shortText`, `longText`, `laws[{code,name,abbr,sections[]}]`, `source`, `litigants`, `judges`, `lowerCourts`, `department`, `blackNo`, `primaryCourtNos`, `remark`, `sourceUrl`, `retrievedAt`

- **dedup ด้วย `docId` ไม่ใช่ caseNo+year**: ในนำร่อง 30 คดีมี 5 คดีที่ caseNo/ปี เดียวกันแต่เป็นคนละระเบียน (คนละเวอร์ชัน/ย่อยาวว่างในอีกอัน) — ตอนโหลดเข้า DB ให้เลือกระเบียนที่ `longText` ยาวที่สุดต่อ caseNo+year
- ข้อความเก็บตาม DOM เดิม (ย่อหน้าต่อด้วย `\n`, ขึ้นต้นย่อหน้าด้วย `\t`) ไม่ผ่าน AI ไม่ตัดต่อ; ไม่พบอักขระซ่อน/เลขหน้า/ส่วนหัวปนในข้อความ; ข้อความต้นฉบับบางคดีเว้นวรรคตกหล่น (เป็นของศาล)

## ประมาณการทั้งคลัง (133,210 คดี)

| รายการ | ประมาณ |
|---|---|
| จำนวนคำขอ | ~6,660 หน้า (20 คดี/หน้า) + 113 ปี × 2 (หน้าแรก+ค้นหา) ≈ **6,900 หน้า** |
| เวลา (หน่วง 3–6 วินาที + โหลด ~2–3 วินาที) | ≈ **10–14 ชั่วโมง** (แนะนำแบ่งรันหลายคืน/ช่วงดึก ปีละชุด) |
| ทราฟฟิกดาวน์โหลด | ~1.4 MB/หน้า ไม่บีบอัด ≈ 9 GB (บีบอัดบนสายน้อยกว่ามาก) |
| ข้อมูลดิบ JSONL | ~15 KB/คดี ≈ **1.5–2.5 GB** (ไทย 3 ไบต์/ตัวอักษร; บีบ zip ได้เหลือ ~25–30%) |
| ใน Postgres | ~0.8–1.0 GB + ดัชนี ~0.5–0.8 GB → เกิน Supabase Free (500 MB) ต้อง Pro หรือโหลดเฉพาะบางส่วน |

## แผนโหลดเข้า Supabase (ยังไม่ทำ)

1. ตรวจรูปแบบ `schema.sql` แล้วย้ายเป็น migration (ตาราง `precedents_full`, RLS: ทุกคนอ่าน/แอดมินเขียนผ่าน `public.is_admin()`)
2. เขียน `load.mjs` (ยังไม่มี): อ่าน `<ปี>.jsonl` → ตัดคำไทยด้วย `Intl.Segmenter('th')` เก็บใน `search_tokens` → แปลง `laws` เป็น `sections text[]` (เช่น `ป.พ.พ. ม. 11`) → เลือกระเบียนซ้ำที่ข้อความยาวสุด → upsert ด้วย `source_doc_id` เป็นชุดละ 500 แถวด้วย service_role key จากเครื่องแอดมินเท่านั้น
3. API ค้นหาต้องตัดคำคำค้นด้วยตัวตัดคำเดียวกัน (ดูหัวข้อในไฟล์ SQL)

## ข้อควรรู้ก่อนรันเต็ม

- **ลิขสิทธิ์/สิทธิ**: เว็บระบุ "© ลิขสิทธิ์โดยศาลฎีกา" แม้ตัวคำพิพากษาไม่เป็นงานอันมีลิขสิทธิ์ตาม พ.ร.บ.ลิขสิทธิ์ ม.7 แต่ย่อสั้น/ย่อยาวเป็นงานเรียบเรียงโดยเจ้าหน้าที่ศาล และฐานข้อมูลเป็นของศาล — เจ้าของแจ้งว่าขอศาลแล้ว **ควรได้หนังสืออนุญาตเป็นลายลักษณ์อักษรก่อนรันเต็มและก่อนเผยแพร่ซ้ำ**
- ข้อมูลส่วนบุคคล: คู่ความบางคดีแสดงชื่อเต็ม (รวมคดีครอบครัว/เยาวชนที่ศาลปิดชื่อไม่ครบ) — พิจารณา PDPA ก่อนเผยแพร่
- ชื่อฟิลด์ "full text" ในผลิตภัณฑ์ควรสื่อว่าเป็น "ย่อยาวตามที่ศาลเผยแพร่" ไม่ใช่ฉบับเต็ม
